CFW500 Modbus IHM HIscada Portal PostgreSQL

Objetivo do Projeto: O cliente precisa controlar a velocidade de um motor usando um inversor de frequência CFW500. Para segurança, ele pediu a instalação de um LED físico. Esse LED funcionará como o alarme do sistema, que deve ser acionado especificamente quando o motor estiver rodando abaixo do limite de 40 Hz.

Como o controle vai funcionar: O sistema terá três formas de acesso:
1. IHM Local (Tela Touch): Será o único lugar onde o operador poderá ligar e desligar o motor (garantindo segurança visual perto da máquina).
2. Supervisório Local (HIscada): Os operadores só poderão visualizar os dados. Já os supervisores terão permissão para enviar comandos. O histórico de dados deve ser salvo em um banco de dados PostgreSQL.
3. Portal na Nuvem: Vai seguir as mesmas regras de permissão do supervisório (visualização para uns, controle para outros).

Organização dos Dados: No CLP, você deve guardar as informações dentro de uma estrutura de dados chamada CFW500. Preste atenção na conversão de dados: os valores de corrente não devem ser convertidos para "Real" (ponto flutuante) direto no CLP. Você deve fazer essa conversão matemática apenas no HIscada e no Portal usando scripts. Além disso, tanto o Portal quanto o HIscada devem gerar um relatório com o nome da HI Tecnologia.

Alertas Automáticos: O sistema precisa enviar notificações por E-mail e Telegram sempre que necessário. O próprio HIscada também deve ter uma configuração para disparar e-mails de alerta de forma automática.

💡 Dica de Comunicação Modbus Para ler e escrever no inversor CFW500, você deve usar o bloco MDB_GATEWAY_EX. Use junto a função NOTIFY para conseguir mandar comandos só quando a condição for verdadeira. Se tiver dúvidas, assista aos vídeos de apoio sobre script, banco de dados, relatórios e comunicação Modbus.
PT100 NTC THT860 THT863 MQTT GTON M PostgreSQL

Objetivo do Projeto: Monitorar a temperatura nos quatro cantos de uma sala de servidores para garantir que o ambiente não aqueça demais.

Sensores e IHM Local: Você vai usar sensores diferentes (PT100, NTC, THT860 e THT863). Os sensores THT precisam ficar instalados em lados opostos da sala para conseguir medir a umidade também. Dentro dessa sala, uma IHM vai mostrar as temperaturas ao vivo e salvar o histórico ali mesmo, para que os técnicos consigam consultar se precisarem.

Comunicação e Internet: Os dados dos sensores vão ser enviados via rádio para um CLP principal (Mestre). Como a sala não tem internet a cabo liberada, esse CLP Mestre vai usar um modem 4G para se conectar e enviar os dados para a nuvem usando o protocolo MQTT.

Supervisório e Banco de Dados: A rede local vai conectar o sistema ao supervisório, que vai gerar relatórios e salvar tudo em um banco de dados PostgreSQL. É muito importante configurar alarmes (tanto na nuvem quanto no supervisório) para disparar se a temperatura cair para 20ºC ou menos, ou subir para 30ºC ou mais.

Notificações: Qualquer alerta da sala de servidores deve chegar para a equipe pelo Telegram e por E-mail. E não esqueça: o próprio HIscada também deve estar configurado para disparar avisos por e-mail.

💡 Dicas Práticas Visualização: No HIscada, use o gráfico do tipo Trend para mostrar como a temperatura está variando.
Nuvem (GTON M): Para conectar usando MQTT com o modem GTON externo, preencha o IP e a Porta do Broker no bloco MQTT GATEWAY do CLP apontando para o GTON, e ele se encarregará de mandar para a nuvem.
Rede de Rádio: Na hora de usar o rádio WSC720, lembre que os cabos certos para conectar ao CLP são os da interface ESC (fios ESC - PLC).
Organização: Crie estruturas de dados (Structs) no software para organizar todas as variáveis de temperatura de um jeito mais limpo.
Vazão PWM FCT IHM Touch HISCADA PRO SQLite

Objetivo do Projeto: Monitorar os pulsos de um medidor de vazão para calcular a quantidade de litros consumidos, exibindo esses dados tanto no formato de vazão instantânea quanto de vazão totalizada.

Regras de Tempo (O Desafio): O valor da vazão totalizada deve ser armazenado temporariamente na memória e enviado ao portal na nuvem exatamente a cada 60 minutos. Atenção: após esse envio, o valor precisa ser resetado (zerado) para recomeçar a contagem do zero. Para os demais dados e dispositivos, as informações podem ser transmitidas normalmente, conforme o intervalo de coleta padrão da sua rede.

Proteção de Dados (Persistência): É fundamental que o valor da vazão totalizada não seja perdido caso você precise desligar o CLP ou ocorra uma queda de energia. Ou seja, esse dado deve ser configurado como persistente na memória.

Monitoramento e Relatórios: O cliente exige a supervisão local desses dados no chão de fábrica por meio de uma IHM touch. Além disso, o processo será monitorado em nuvem e também por meio do software HISCADA PRO. Em ambos os sistemas (Nuvem e HISCADA) deverão ser gerados relatórios de processo, sendo que no HISCADA PRO é obrigatória a utilização do banco de dados SQLite.

Alertas e Notificações: O cliente solicita o envio automático de notificações por E-mail e Telegram sempre que ocorrerem casos de desconexão, e também para receber um resumo diário do processo. Adicionalmente, o HISCADA PRO deve enviar um E-mail ao cliente a cada 1 hora, relatando com exatidão o valor da vazão total acumulada naquele ciclo.

💡 Dica de Lógica (PWM e FCT) Para montar a lógica, use o bloco PWM com uma frequência baixa para imitar os pulsos físicos do sensor. Em seguida, use o bloco FCT para contar esses pulsos e transformar esse valor em vazão instantânea. A partir daí, é só usar matemática básica no CLP para chegar na vazão acumulada geral e na acumulada por hora.
ZAP900 MODBUS RTU RS485 MODSIM IHM HISCADA PRO

Objetivo do Projeto: Fazer o controlador ZAP900 se comunicar com um transmissor de temperatura da Novus (que será simulado pelo aplicativo MODSIM) através da rede Modbus RTU RS485.

O que o CLP vai fazer: Você precisa programar o CLP para enviar (escrever) o valor desejado de SetPoint (SP) para o transmissor simulado e, ao mesmo tempo, ficar lendo qual é a temperatura atual, que chamamos de Variável de Processo (PV).

Interface IHM: O operador deve conseguir ir até a IHM, digitar o valor do SetPoint (SP) que ele deseja e ver na mesma tela qual é a temperatura atual (PV).

Regras Lógicas do Processo:
▶ O processo da máquina só pode iniciar quando a temperatura (PV) chegar a 50ºC.
⏹ O processo deve desligar sozinho assim que a temperatura atingir 100ºC.
💡 Você deve colocar um LED que acenda para avisar que o processo está em funcionamento.

Supervisão e Histórico: Tudo isso precisa ser controlado pelo HISCADA PRO, que também vai gerar um relatório do processo. Não esqueça de criar um alarme no HISCADA PRO que dispare toda vez que a temperatura cair abaixo de 50ºC.

💡 Dica de Simulação de Temperatura Depois que você der o comando para enviar o SetPoint para o Modsim, crie uma lógica no CLP usando temporizadores (timers) para ir subindo a temperatura (PV) bem devagarzinho. Escreva esse valor no MODSIM para simular que está esquentando de verdade. O CLP vai ler esse valor de volta via Modbus e, quando a temperatura (PV) se igualar ao SetPoint (SP), você desliga o comando de escrita.
💡 Configuração Modbus RTU Para garantir a comunicação correta da leitura e escrita com equipamentos escravos pela rede RS485, você deve usar o Bloco SCB no ladder.
📈 Visualização no HISCADA PRO Para o visual do projeto ficar bacana e profissional, use o gráfico do tipo Trend no HISCADA PRO para mostrar a linha da Temperatura (PV) junto com a linha do SetPoint (SP).
